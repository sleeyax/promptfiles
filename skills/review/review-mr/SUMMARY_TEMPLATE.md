# Summary draft-note template

Fill this shape once per review and post as a non-positional draft note.

```
## Code review summary

<2-4 plain sentences in first person: what to act on first, what was reviewed, what was deliberately left out, and the effort involved. State here if the review was diff-only (no local checkout).>

### Reviewers

<Reviewed independently by M agents. A findings were raised by both.>

- **<agent>** `<model>` — N findings
- **<agent>** `<model>` — M findings

<details>
<summary>N files reviewed</summary>

- `path/a`
- `path/b`

</details>

> [Generated by AI](https://github.com/sleeyax/skills/blob/main/skills/review/review-mr/SKILL.md) (agent: `<agent>`, model: `<model>`).
```

## Rules

Structure beats density here: the note is read in a narrow MR column, so every list goes vertical and nothing gets packed onto one line with separators.

- **Body**: first person (`I`), one paragraph, no bullets, no headers, no score. Never hard-wrap it — let the renderer wrap. Lead with the finding worth acting on first — one both reviewers raised if they converged, otherwise the highest severity — then what was reviewed, anything deliberately out of scope, and for single-sourced findings that you verified them yourself. Close with an effort estimate in plain English (`a small fix`, `moderate rework`, `substantial redesign`). The **Reviewers** section carries the agreement count, so don't restate it. Mention diff-only mode here when applicable.
- Don't tally findings by severity or list them here. Each one is already its own comment on the thread, carrying its own severity, and the developer scans those — repeating them turns the summary into an index of the page it sits on. The summary's job is the verdict and the provenance, nothing the reader can get by scrolling.
- **Reviewers**: one line on how many agents ran and how far they agreed — convergence is the one signal the inline comments can't show, since a finding both agents reached looks identical to one only a single agent raised. Then one bullet per reviewer with its raw finding count, before deduplication. Omit the whole section when a single reviewer ran — the footer already names it.
- **Files reviewed**: every path, one per line, never truncated — the `<details>` is what keeps a long list from swamping the note. The count is the files that were in scope for the review, not a per-reviewer coverage claim. Keep the blank lines around the list: GitLab won't render markdown inside `<details>` without a blank line after `<summary>`.
- **Footer**: substitute `<agent>` with the agent name (e.g. `Claude Code`, `Codex CLI`) and `<model>` with the model identifier in use (e.g. `claude-opus-5`, `gpt-5.6-sol`). Both stay inside the backticks. Don't leave the placeholders literal.
  - When the **Reviewers** section is present it carries the attribution, so the footer drops the parenthetical: `> [Generated by AI](…).`
